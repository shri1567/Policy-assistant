# Policy Q&A Assistant with Evidence

A retrieval-augmented Q&A system over a company's HR/IT policy collection. Answers only
from retrieved policy evidence, cites the source document + section, exposes a debug
trace for every question, and refuses to answer when evidence is insufficient.

See `SPEC.md` for design decisions and `AGENTS.md` for how the LangGraph pipeline works.

## Stack
- FastAPI + Pydantic — API layer
- A local JSON file (`data/store.json`) — stores policy chunks + their embeddings, with
  cosine similarity search done in plain Python. No database server to install or run.
- Gemini API (Google AI Studio) — embeddings (`gemini-embedding-001`) + generation (`gemini-3.6-flash`)
- LangGraph — retrieve → generate_answer → validate_citations
- `uv` — dependency management
- A small vanilla HTML/JS frontend (`app/static/index.html`) for interactive use, in
  addition to the raw API

**Note on model names:** Google retires Gemini model versions fairly often. If you hit a
`404 NOT_FOUND` error on ingestion or a question, the model name in `.env` has likely
been deprecated since this was written — check
[ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models) for
the current stable model names and update `EMBEDDING_MODEL` / `GENERATION_MODEL` accordingly.

## Setup

1. Get a free Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey).
2. Copy `.env.example` to `.env` and fill in `GOOGLE_API_KEY`.
3. Install dependencies:
   ```bash
   uv sync
   ```
4. Run the app:
   ```bash
   uv run uvicorn app.main:app --reload
   ```
   On first run this creates `data/store.json` automatically — nothing else to set up.
5. Open `http://localhost:8000/` in your browser for the interactive UI, or ingest via
   curl:
   ```bash
   curl -X POST http://localhost:8000/documents/ingest
   ```

No Docker, no cloud database signup required.

## Using it

- **`http://localhost:8000/`** — a simple chat-style page: click "Ingest documents" once,
  then type a question and get an answer with a supported/refused badge, cited sources,
  and a collapsible "show evidence" section.
- **`http://localhost:8000/docs`** — the full interactive API reference (Swagger UI,
  auto-generated by FastAPI), useful for testing individual endpoints or inspecting exact
  request/response shapes.

## API

| Endpoint | Purpose |
|---|---|
| `GET /` | The interactive frontend page. |
| `POST /documents/ingest` | Ingest all documents in `data/manifest.json`. Idempotent — returns a summary (`total_documents`, `ingested`, `skipped_duplicate`, `failed`, `total_chunks_created`) plus per-document results. |
| `POST /documents/ingest/upload` | Ad-hoc single-file upload ingestion. |
| `GET /documents` | List ingested documents with chunk counts. |
| `POST /questions` | Ask a question. Returns the schema below. |
| `GET /questions/{id}` | Retrieve a previously asked question's answer. |
| `GET /questions/{id}/debug` | Full retrieval + generation trace for a question. |

### `/questions` response schema
```json
{
  "question_id": "uuid",
  "answer": "string",
  "supported": true,
  "citations": [{"document_id": "POL-001", "document_title": "Leave Policy", "section": "Section 2"}],
  "retrieved_sources": [{"document_id": "...", "section": "...", "text": "...", "score": 0.83}],
  "confidence": 0.83,
  "reason_for_refusal": null
}
```

### `/documents/ingest` response schema
```json
{
  "total_documents": 6,
  "ingested": 6,
  "skipped_duplicate": 0,
  "failed": 0,
  "total_chunks_created": 42,
  "results": [{"document_id": "POL-001", "file_name": "leave_policy.md", "status": "ingested", "chunks_created": 7}]
}
```

## Running tests

Fast unit tests (chunking, hashing, citation-validation logic — no API key needed):
```bash
uv run pytest tests/test_ingestion.py tests/test_graph.py -v
```

Full API tests (needs `GOOGLE_API_KEY` set, since these call the real Gemini API):
```bash
export GOOGLE_API_KEY=your_key_here
uv run pytest tests/test_api.py -v
```

## Running the evaluation

```bash
uv run python -m app.evaluate
```

Reports retrieval hit rate, citation correctness, supported-answer accuracy, and
unsupported-question refusal rate against `data/eval/eval_questions.json` (20 questions:
10 supported, 4 multi-document, 3 ambiguous, 3 unsupported).

## Project structure
```

  main.py       - FastAPI routes, including / (UI) and /docs (Swagger, automatic)
  graph.py      - LangGraph: retrieve -> generate_answer -> validate_citations
  ingest.py     - section-aware chunking + dedup ingestion
  llm.py        - Gemini embedding/generation wrapper
  db.py         - local JSON file storage + hand-written cosine similarity
  schemas.py    - Pydantic request/response models
  evaluate.py   - eval harness against data/eval/eval_questions.json
  static/
    index.html  - the interactive frontend page, served at /
data/
  policies/     - 6 source policy documents (markdown)
  manifest.json - document metadata for ingestion
  eval/         - evaluation question set with expected evidence
  store.json    - generated on first run; holds embeddings (not committed to git)
tests/
  test_ingestion.py  - chunking, hashing, dedup, unsupported/empty file handling
  test_graph.py      - citation validation logic (unit, no infra)
  test_api.py        - end-to-end scenarios (needs GOOGLE_API_KEY)
SPEC.md         - design decisions, data flow, failure-handling map
AGENTS.md       - LangGraph node behavior and why the graph is linear, not looping
```
## Known limitations
- No auth — single-tenant, internal-tool assumption.
- The local JSON store re-computes similarity against every chunk on every question
  (fine for a handful of policy documents; wouldn't scale to a large collection —
  see `SPEC.md` Section 3 for the pgvector tradeoff this made).
- Retrieval is single-hop; genuinely multi-hop reasoning questions rely on the
  top-k window catching all relevant chunks in one pass (see `AGENTS.md`).
  `DEFAULT_TOP_K` in `.env` defaults to 6 (raised from an initial 4 after testing
  showed multi-document questions needed more retrieval breadth) — raise it
  further if a specific multi-document question is still missing relevant evidence.
- Gemini model names change over time as Google retires older versions — see the note
  under Stack above .
